# 声音提醒 0.3.0 预览版

会话本轮任务正常结束、出现待审批请求时，让运行 QwenPaw 的电脑播放系统提示音。无需让模型调用工具，不消耗模型 token。

## 先确认运行环境

- 最低支持 **QwenPaw 2.0.0**。已用 2.0.0、2.0.1、2.1.0、2.2.0 beta.3 和当前 2.2.1b2 的源码分别通过兼容测试。未来版本接口如果变化，需要重新验证；不保证未发布版本一定可用。
- **声音在 QwenPaw 后端所在电脑播放**。本地桌面运行适用；远程服务器、Docker、无桌面环境不保证能发声，也不会让访问 Console 的另一台电脑发声。
- macOS：默认完成使用 Glass，审批使用 Ping；设置页可选择系统目录中的其他铃声并调节音量。已实机验证。
- Windows：列出 Windows Media 目录中的 WAV 系统铃声，使用 `winsound.PlaySound` 播放，通过调整 PCM 数据控制音量；不修改系统总音量。尚未实机测试。
- Linux：优先 `canberra-gtk-play`，其次 `paplay` + freedesktop 提示音主题；需要可用的桌面音频会话，尚未实机测试。

## 安装测试

解压插件包后，使用目标 QwenPaw 环境中的命令安装：

```sh
qwenpaw plugin install /path/to/system-sound
```

将 `/path/to/system-sound` 替换为解压后的插件目录。如果运行了多个实例，请通过 `QWENPAW_WORKING_DIR` 指定目标服务的数据目录。当前终端所在的源码目录不会决定安装目标。

也可以打开目标实例的插件管理页，上传 `system-sound-0.3.0.zip`。已经安装过插件时，在安装命令末尾加 `--force` 更新。安装后请确认插件已启用。

安装后启动 QwenPaw；如果服务已运行，正常情况下安装会热加载。如果未生效，重启 QwenPaw 一次。

测试步骤：

1. 发一个普通任务，等待整轮回复结束，应该听到一次完成音。
2. 使用你原有的审批规则，触发一个需要确认的操作；审批出现时应该听到一次提醒，批准或拒绝本身不会另响。
3. 取消一个仍在运行的任务，不应播放完成音。
4. 可关闭 Console 页面再测试，提示音不依赖页面是否打开。

排查音频可单独运行（不要求导入 QwenPaw）：

```sh
python /path/to/system-sound/plugin.py --test completion
python /path/to/system-sound/plugin.py --test approval
```

若命令成功但没有听到声音，检查系统音量、静音、输出设备和运行用户的桌面音频会话。插件后台播放失败时会写入 `qwenpaw.plugins.system_sound` 日志，不会打断任务。

卸载：

```sh
qwenpaw plugin uninstall system-sound
```

## 设置页面

刷新 Console，点击侧边栏 **声音提醒**。设置页面位于当前实例的 `/system-sound` 路径。

- **任务完成／等待审批**：独立开关、铃声下拉选择和试听按钮。
- **仅主任务完成时提醒**：默认开启，只过滤完成音；关闭后恢复每个会话正常结束时提醒。
- **提示音音量**：0–100%，0 为静音，只控制本插件。
- **试听**：按页面当前选择试听，不保存设置；即使提醒关闭，也可试听。
- **保存设置**：立即生效，无需重启；刷新页面后仍保留。
- **撤销修改**：恢复最近保存的设置。

设置对该 QwenPaw 实例的所有会话生效，声音仍在后端所在电脑播放。

设置保存于 `$QWENPAW_WORKING_DIR/plugin_settings/system-sound.json`。文件位于插件目录之外，升级、卸载重装都会保留。只有保存成功后才改变生效设置；保存失败会在页面报错。

旧版 `settings.json` 仅用于第一次启动时迁移开关；有独立设置文件后不再读取它。手动编辑独立文件后需重启；通过设置页面保存则无需重启。跨操作系统迁移时，不可用铃声回退为系统默认。

后端接口（使用 Console 的认证请求）：

- `GET /api/system-sound/settings`：当前设置、操作系统和可选系统铃声。
- `PUT /api/system-sound/settings`：验证并保存完整设置。
- `POST /api/system-sound/preview`：试听，失败会明确返回错误。

前端入口 `frontend.js` 直接使用宿主提供的 React / Ant Design，不需要 npm 安装或构建。

## 当前边界与后续工作

- **已实现“仅主任务完成时提醒”**，默认开启，可在设置页关闭。关联子任务不单独响；主 agent 回复正常结束时，若还有子任务或后台工具在执行，也不响。后台任务后来结束本身不会发声，主 agent 后续正常回复、且关联任务全部结束时才响。
- 覆盖本实例标准工具的 `chat_with_agent`、`submit_to_agent`、`spawn_subagent`（前台／后台／batch／fork），以及它们的嵌套调用。开启开关时，审批提醒仍按审批开关独立执行，子任务申请审批不会被静音。
- 主任务失败／取消不播放完成音。子任务失败或超时可以作为已结束的结果；主 agent 正常回复并说明这些结果时可以响，不把失败误当成任务成功。
- 不同顶层会话分别判断，不会因为另一位 agent 的独立任务还在运行就一直静音。
- 插件不会自动唤醒主 agent，也不检查它是否真的理解、采纳了子任务结果。若主 agent 没有回来汇总，子任务完工不会代替主任务发声。
- 调用关系通过插件附加的 `request_context` 标记传递。后台状态来自本实例任务表，未知状态会保持静音。第三方自建工具／远程 QwenPaw 实例／脱离宿主跟踪的进程不属于已验证范围。安装前就已运行的任务没有完整调用链，请用安装后的新任务测试。
- 设置和开关会持久保存；调用链只保留在内存中，插件热更新会复用跟踪状态，服务重启不恢复已经中断的任务。计划在未来执行的定时任务不算当前主任务的未完成子任务，单次定时触发按自己的任务判断。
- “完成”指本轮 Runtime 正常结束，不代表用户的整个长期目标已经达成，也不检查回答语义。没有把模型的每次中间回复或每次工具调用当作完成。
- 目前不区分 Console、其他频道、定时任务或自动唤醒；它们经过相同 Runtime 时也会提醒。
- 错误／取消不播放完成音；未建立 agent 的控制命令不响。
- 独立线程串行播放，最多排队 16 个提醒；超出后丢弃新提醒并记录日志。卸载后丢弃排队提醒，已经开始的系统音可能继续播放到结束。
- 审批覆盖 `ApprovalService.create_pending` 和 `create_pending_summary`。当前没有公开审批监听接口，因此插件包装了这两个方法。卸载会恢复原方法；若其他插件后来包装了同一方法，会保留其他插件并停用本插件的回调。
- 任务完成使用 `register_runtime_hook`。当前宿主没有公开的运行时 hook 卸载接口，插件卸载时按对象身份清理自身 hook，升级宿主时需重新验证这部分兼容性。

旧版 QwenPaw 的版本格式没有“无上限”写法：省略 `max` 会自动限制为 `<2.1.0`。平台还要求 `max` 的主版本为 1 或 2，因此清单使用 `min: 2.0.0, max: 2.999.999`（不含上限），覆盖常规 2.x 版本。3.x 发布后需要重新验证并更新声明。这是版本声明兼容处理，不是对未来接口的测试结论。

另在临时目录使用真实 `PluginLoader` 完成两轮安装、启动、卸载及重新加载，核对审批方法恢复和运行时 hook 清理。macOS 两种系统音命令均成功。

设置页面已验证铃声选择、音量调整、开关、试听、保存及刷新保留。Windows/Linux 的真实设备、旧版 Console 页面以及实际审批弹出的声音仍未做端到端验证。0.3.0 的多智能体逻辑使用可控的任务结果测试，尚未用真实模型跑完整协作任务。
